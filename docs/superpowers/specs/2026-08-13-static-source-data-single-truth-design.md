# 정적 원천 데이터 단일화 설계

## 목표

기존 합성 엑셀 산출물에서 추출한 일별 KPI·변수 데이터와 시간별 공정 데이터를 유일한 정적 원천으로 사용한다. 사용자가 날짜, 시간, 기간을 변경하면 선택 구간의 실제 원천 레코드만으로 모든 KPI, 이상진단, 손익영향, 표 및 그래프를 재계산한다.

## 데이터 원천과 경계

- `daily-observations.js`: `COG_합성데이터_2024_2025.xlsx`의 일별 KPI 집계에서 추출한 731일 데이터
- `cost-observations.js`: 같은 통합 엑셀의 시간단위 공정데이터에서 추출한 17,544시간 데이터
- `source-standards.js`: `COG_관리기준표.xlsx`에서 추출한 관리기준 및 적용시점
- `data-service.js`: 화면이 호출하는 유일한 조회·계산 인터페이스

`data.js`에 남아 있는 폴백 일별·원가 레코드는 런타임에서 사용하지 않도록 제거하거나 원천 파일이 없는 개발 환경용으로 명시적으로 격리한다. 화면 컴포넌트는 로컬 고정 수치나 자체 계산을 갖지 않는다.

## 조회 규칙

- 일별 KPI·변수는 선택 구간에 속한 일별 레코드를 조회하며, 종료 시점의 레코드로 현재값을 표시한다.
- 시간 입력이 있으면 손익은 해당 시작·종료 시각 사이의 시간별 원천 레코드만 집계한다. 일자만 입력하면 해당 일자의 00:00:00~23:59:59를 집계한다.
- 이상진단은 선택 구간과 겹치는 이벤트 및 해당 기간의 관리기준 이탈 KPI만 표시하며, 없으면 이상 없음으로 표시한다.
- 관리기준은 각 관측일의 적용시점을 기준으로 판정한다.
- 모든 화면은 동일한 `CogDataService` 결과만 사용한다.

## 검증

자동 테스트는 원천 레코드 직접 변경, 인접 일자, 시간 단위, 짧은 기간, 이벤트 없음/있음 시나리오를 검증한다. Playwright E2E는 각 주요 화면에서 기간 변경 전후의 표시값이 실제로 변하는지 검증한다.

## 비범위

DB, API, 백엔드와 UI 레이아웃 변경은 포함하지 않는다. 다음 단계에서 데이터 서비스 내부의 정적 원천만 DB/API 호출로 대체한다.

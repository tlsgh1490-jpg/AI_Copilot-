# 동적 Brief 문구 설계

## 목적

`_analysis_work/build_analysis_data.py`의 시나리오별 고정 결론 문구 의존을 줄이고, 조회 시점의 실제 운영 데이터·관리기준·판정 결과를 NVIDIA NIM LLM에 전달해 Brief 문구를 생성한다. 수치 판정과 연속 이탈 규칙은 LLM이 아니라 기존 결정 로직이 담당한다.

## 역할 분리

- 원본 공정·단가 데이터는 사용자가 관리하며 코드가 덮어쓰지 않는다.
- 빌드 스크립트는 기존 `analysis_data.json` 호환 구조와 최소 대체 문구만 유지한다. 시나리오 이름과 고정 원인 결론으로 Brief를 만들지 않는다.
- 서버 Copilot은 선택 기간의 DB 데이터에서 이탈 지표, 관리기준 대비 차이, 연속 이탈 일수, 손익 영향, 관계·가중치와 상관계수를 계산한다.
- NVIDIA LLM은 계산 결과만 받아 아래 JSON 구조의 설명 문구를 생성한다.

```json
{
  "예상원인": "확정 원인이 아닌 데이터 기반 점검 후보",
  "영향KPI": "영향 지표 목록",
  "점검우선순위": "즉시 점검 가이드",
  "brief_summary": "주의 또는 이상 상태의 간결한 요약"
}
```

## 처리 흐름

`원본 데이터 → DB 가져오기 → 수치 판정/관계 분석 → LLM 설명 생성 → 기존 Brief 화면`

LLM JSON이 형식에 맞지 않거나 API 키·네트워크·시간 제한 문제가 생기면, 계산 결과로 만든 대체 문구를 사용한다. 원인 단정이나 제공되지 않은 수치 생성은 금지한다.

## 호환성과 검증

- 기존 프론트엔드가 쓰는 `daily_status`, `event_analysis` 키와 기존 화면 데이터 구조는 유지한다.
- 새 LLM 설명은 별도 필드로 보관하고, 기존 필드가 없는 경우에도 화면이 깨지지 않게 한다.
- 테스트는 정상 JSON, 잘못된 JSON, API 실패, 대체 문구, 같은 조건의 캐시 재사용을 확인한다.

## 범위

이번 작업은 Brief 분석 문구와 서버 응답을 동적으로 만드는 데 집중한다. 원가 계산식, 공정 데이터·단가 데이터의 기존 계산 규칙과 화면 흐름은 변경하지 않는다.
